INIT SAAS PLATFORM
ETAPA 028 - ASSINATURA RECORRENTE ASAAS SANDBOX

DECISÃO ARQUITETURAL

Em vez de criar uma cobrança avulsa por ciclo, esta etapa usa o
recurso de ASSINATURAS RECORRENTES do Asaas.

Motivo:
o próprio Asaas gera as próximas cobranças de acordo com o ciclo,
o que combina melhor com SaaS e reduz jobs próprios de criação de
cobranças.

A Init continua sendo dona de:
- contrato;
- status comercial;
- valor contratado;
- próxima cobrança;
- tolerância;
- suspensão;
- auditoria.

O Asaas fica responsável por:
- gerar cobranças;
- disponibilizar meios de pagamento;
- informar eventos por webhook.

IMPORTANTE

Criar a assinatura no Asaas NÃO significa que houve pagamento.

O pagamento só será considerado confirmado quando o webhook de
cobrança for processado em uma etapa posterior.

BILLING TYPE

Nesta primeira homologação:

UNDEFINED

Isso permite trabalhar com a Fatura do Asaas sem decidir agora que
todo cliente obrigatoriamente usará PIX, boleto ou cartão.

IDEMPOTÊNCIA

Fluxo:

1. verifica vínculo local;
2. busca no Asaas por externalReference;
3. só cria se não encontrar;
4. persiste o ID remoto;
5. advisory lock por assinatura.

externalReference:

init_assinatura_<ID>

Exemplo:

init_assinatura_2

Se a chamada ao Asaas criar a assinatura mas houver falha antes do
INSERT local, uma nova execução recupera a assinatura remota pelo
externalReference em vez de criar outra.

O número de cobranças geradas é retornado pela API logo após a
criação. Dependendo do comportamento do Sandbox, confirme também
pela interface do Asaas.

SEGUNDO TESTE

Execute novamente o mesmo comando.

Esperado:

Nenhuma segunda assinatura remota deve ser criada.

NO ASAAS

Confira:
- Cobranças / Assinaturas;
- cliente correto;
- valor correto;
- periodicidade;
- data da primeira cobrança;
- somente uma assinatura recorrente.

SEGURANÇA FINANCEIRA

O valor:
- vem do banco;
- não vem do terminal/browser;
- continua NUMERIC no PostgreSQL;
- não sofre cálculo em float.

Há uma conversão para número JSON somente na fronteira HTTP porque
a API Asaas exige o campo value como number.

AUDITORIA

Evento:

ASSINATURA_GATEWAY_VINCULADA

O log não grava:
- API key;
- CNPJ;
- e-mail;
- telefone;
- corpo integral da API.
